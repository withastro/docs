API keys allow you to interact with Prosopo services programmatically — for example, managing access control rules, provisioning sites or querying traffic data from your backend without using the portal UI. Every endpoint a key can call is listed in the [API reference](/en/advanced/api/).

API keys are not used for CAPTCHA verification. [`/siteverify`](/en/basics/server-side-verification/) authenticates with your site's secret key instead.

API key management is available to accounts with the API feature enabled. It is off by default — contact support to have it turned on.

## Creating an API key

1. Log in to the [Prosopo Portal](https://portal.prosopo.io)
2. Navigate to **API Keys** from the main menu
3. Click **Create API Key**
4. Fill in the required fields:
   - **Name** (required): A descriptive label for the key, e.g. "Production Backend" or "CI/CD Pipeline"
   - **Expiration Time** (optional): Time in seconds until the key expires. Leave it empty, or enter `0`, for a key that does not expire.
   - **Permissions** (required): Select which operations this key can perform (see below)
5. Click **Create API Key**

<Image src={ApiKeyCreate} alt="prosopo portal create API key dialog" style="margin: 20px auto;"/>

The key stays available after creation: it is listed on the API Keys page, hidden until you click to show it, and is also returned by [`/api-keys/get`](/en/advanced/api/#api-keys). Treat that page and that endpoint as secret.

## Permissions

Each API key is scoped to a set of permissions, and each permission opens exactly one endpoint, so you can
grant a key the endpoints it calls and nothing more. A section only appears when the matching feature is
enabled on your account. Every section has a **Select all**, and the longer ones (Access rules and Protect)
are split into groups that can be selected at once.

### Access rules

| Permission | Endpoint |
|-----------|-------------|
| `getRules` | List access control rules (`/access-control/get`) |
| `createRule` | Add an access control rule (`/access-control/create`) |
| `createRuleGroup` | Add a group of access control rules (`/access-control/group/create`) |
| `deleteRule` | Delete an access control rule (`/access-control/delete`) |
| `deleteRuleGroup` | Delete a group of access control rules (`/access-control/group/delete`) |
| `createReport` | Create a report (`/reports/create`) |

### Sites

| Permission | Endpoint |
|-----------|-------------|
| `getSite` | Read one site (`/site/get`) |
| `getSites` | List every site (`/sites/get`) |
| `createSite` | Create a site (`/sites/create`) |
| `updateSite` | Change a site's name or settings (`/sites/update`) |
| `deleteSite` | Delete a site (`/sites/delete`) |

### API keys

| Permission | Endpoint |
|-----------|-------------|
| `createApiKey` | Create API keys (`/api-keys/create`) |
| `deleteApiKey` | Delete API keys (`/api-keys/delete`) |

There is no way to edit a key's permissions after creation. To change them, create a replacement key and delete the old one.

### Users

| Permission | Endpoint |
|-----------|-------------|

| `createUser` | Invite team members (`/users/create`) |
| `updateUser` | Change a team member (`/users/update`) |
| `deleteUser` | Remove team members (`/users/delete`) |

### Traffic

## Using an API key

Include the API key in the `Authorization` header of your HTTP requests. This example lists your access control rules and needs the `getRules` permission:

```bash
curl -X POST https://api.prosopo.io/access-control/get \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Or in code:

```javascript
const response = await fetch('https://api.prosopo.io/access-control/get', {
  method: 'POST',
  headers: {
    'Authorization': `Bearer ${apiKey}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({}),
});
```

See the [API reference](/en/advanced/api/) for every endpoint, its permission and its request body.

## Managing API keys

### Viewing keys

The API Keys page shows all keys for your account. Each one displays:

- **Name**: The label you gave the key
- **Token**: The key itself, hidden until you click to show it
- **Expires At**: When the key expires, or "Never" for non-expiring keys
- **Permissions**: Which operations the key can perform

### Deleting keys

To revoke an API key, click **Remove** on it in the API Keys list. The key is immediately invalidated — any requests using it will be rejected.

Deletion is permanent and cannot be undone. If you delete a key by mistake, create a new one and update your application with the new key.

## Security best practices

### Principle of least privilege

Only grant the permissions each key actually needs. A key used solely to sync access control rules needs `getRules`, `createRule` and `deleteRule` — it does not need `createSite` or `deleteUser`.

### Use expiring keys for temporary access

When granting access to a contractor, CI/CD pipeline, or temporary integration, set an expiration time so the key is automatically invalidated.

### Rotate keys regularly

For long-lived production keys, rotate them periodically:

1. Create a new key with the same permissions
2. Update your application to use the new key
3. Verify the new key works
4. Delete the old key

### Never expose keys client-side

API keys should only be used in server-side code. Never embed them in frontend JavaScript, mobile apps, or public repositories. For client-side CAPTCHA integration, use site keys instead — see [Client-side Rendering](/en/basics/client-side-rendering/).

### Monitor usage

Review the Audit page and traffic analytics to detect any unexpected API key usage patterns that could indicate a compromised key.
