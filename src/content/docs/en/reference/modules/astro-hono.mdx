The `astro/hono` module provides [advanced routing](/en/guides/routing/#advanced-routing) handlers built as Hono-compatible wrappers.

## Imports from `astro/hono`

```ts
import {
  FetchState,
  astro,
  actions,
  cache,
  i18n,
  middleware,
  pages,
  redirects,
  sessions,
  trailingSlash,
} from "astro/hono";
```

The `astro/hono` module exports the same handler names as [`astro/fetch`](/en/reference/modules/astro-fetch/), but each returns a Hono middleware function. This lets you mix Astro handlers with any Hono middleware from the ecosystem.

Handlers pass the request to the next handler by calling `next()`, or end the chain by returning a response without calling `next()`. Handlers mounted after one that ends the chain do not run for that request:

- `astro()` and `pages()` always return a response and never call `next()`. Mount them last. Handlers that post-process the response, such as `i18n()`, must be mounted before them.
- `trailingSlash()` and `redirects()` return a redirect response when the request needs one, and otherwise call `next()`.
- `actions()` returns the response for action RPC requests, and otherwise calls `next()`. Mount `middleware()` before `actions()` if your middleware needs to run for RPC requests.
- `cache()` can return a cached response without calling `next()` when a runtime cache provider has a cache hit.
- `middleware()` calls `next()` only when your middleware calls `next()`. If your middleware returns its own response, the chain ends.
- `sessions()` and `i18n()` always call `next()`.
