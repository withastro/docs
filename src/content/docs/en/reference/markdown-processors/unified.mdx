[Unified](https://unifiedjs.com/) is a popular ecosystem for processing Markdown with remark and rehype plugins. Astro provides optional support for Unified through the `@astrojs/markdown-remark` package. This allows you to customize and extend the rendering process with remark and rehype plugins. It also provides a set of helpers and types helpful when building integrations or plugins.

For features and usage examples, see [Markdown processors](/en/guides/markdown-content/#markdown-processors) in the Markdown guide.

## Imports from `@astrojs/markdown-remark`

The following helpers are imported from `@astrojs/markdown-remark`:

```ts
import {
  createMarkdownProcessor,
  isUnifiedProcessor,
  parseFrontmatter,
  rehypeHeadingIds,
  unified,
} from "@astrojs/markdown-remark";
```

### `createMarkdownProcessor()`

<p>

**Type:** <code>(opts?: <a href="#astromarkdownoptions">AstroMarkdownOptions</a>) => Promise\<<a href="#markdownrenderer">MarkdownRenderer</a>\></code><br />
<Since v="3.2.0" pkg="@astrojs/markdown-remark" />
</p>

Creates a standalone Unified-based Markdown renderer. This is useful when you need to render Markdown independently of a project's [configured `markdown.processor`](/en/reference/configuration-reference/#markdownprocessor).

```ts title="src/utils/markdown.ts"
import { createMarkdownProcessor } from "@astrojs/markdown-remark";

const processor = await createMarkdownProcessor();
const { code } = await processor.render("# Hello world");
```

### `isUnifiedProcessor()`

<p>

**Type:** `(p: { name: string; }) => boolean`<br />
<Since v="7.2.0" pkg="@astrojs/markdown-remark" />
</p>

Determines whether the given processor is a Unified Markdown processor. This is useful when you need to check the type of a processor before applying Unified-specific logic.

The following example checks, within an integration, whether the configured Markdown processor is a Unified processor:

```ts title="src/integrations/my-integration.ts"
import { isUnifiedProcessor } from "@astrojs/markdown-remark";

export default function myIntegration() {
  return {
    name: "my-integration",
    hooks: {
      "astro:config:done": ({ config }) => {
        if (isUnifiedProcessor(config.markdown.processor)) {
          // Apply Unified-specific logic here
        }
      },
    },
  };
}
```

### `rehypeHeadingIds()`

<p>

**Type:** <code><a href="#rehypeplugin">RehypePlugin</a></code><br />
<Since v="1.2.0" pkg="@astrojs/markdown-remark" />
</p>

Generates and collects heading IDs for all headings in the Markdown content. This makes them [available when importing or rendering Markdown content](/en/guides/markdown-content/#available-properties).

<ReadMore>See [heading IDs and plugins](/en/guides/markdown-content/#heading-ids-and-plugins) in the Markdown guide for usage example.</ReadMore>

### `unified()`

<p>

**Type:** <code>(opts?: <a href="#unifiedprocessoroptions">UnifiedProcessorOptions</a>) => <a href="#markdownprocessor">MarkdownProcessor</a></code><br />
<Since v="7.2.0" pkg="@astrojs/markdown-remark" />
</p>

Creates a Unified-based Markdown processor to render `.md` and `.mdx` files. Pass options to customize the processor's behavior, such as [adding remark or rehype plugins](/en/guides/markdown-content/#markdown-processor-plugins).

The following types are imported from `@astrojs/markdown-remark`:

```ts
import type {

  RehypePlugins,
  RemarkPlugin,
  RemarkPlugins,
  RemarkRehype,
  ShikiConfig,
  Smartypants,
  SyntaxHighlightConfig,
  SyntaxHighlightConfigType,
  UnifiedProcessorOptions,
```

### `AstroMarkdownOptions`

<p>

**Type:** `object`<br />
<Since v="7.2.0" pkg="@astrojs/markdown-remark" />
</p>

Describes the options available for configuring the Unified-based Markdown processor.

#### `AstroMarkdownOptions.syntaxHighlight`

<p>

**Type:** <code><a href="#syntaxhighlightconfig">SyntaxHighlightConfig</a> | <a href="#syntaxhighlightconfigtype">SyntaxHighlightConfigType</a> | false</code>
</p>

Specifies the syntax highlighting configuration for the Markdown processor. Set to `false` to disable syntax highlighting.

#### `AstroMarkdownOptions.shikiConfig`

<p>

**Type:** <code><a href="#shikiconfig">ShikiConfig</a></code>
</p>

Specifies the Shiki configuration for the Markdown processor.

#### `AstroMarkdownOptions.image`

<p>

**Type:** <code>\{ domains?: string[]; remotePatterns?: <a href="/en/reference/modules/astro-assets/#remotepattern">RemotePattern[]</a>; \}</code>
</p>

Specifies the image configuration for the Markdown processor, including allowed domains and remote patterns.

#### `AstroMarkdownOptions.gfm`

<p>

**Type:** `boolean`
</p>

Toggles GitHub Flavored Markdown (GFM) support in the Markdown processor.

#### `AstroMarkdownOptions.smartypants`

<p>

**Type:** <code>boolean | <a href="#smartypants">Smartypants</a></code>
</p>

Controls smart punctuation transformations in the Markdown processor. Set to `false` to disable smart punctuation, or provide a configuration object to customize its behavior.

#### `AstroMarkdownOptions.remarkPlugins`

<p>

**Type:** <code><a href="#remarkplugins">RemarkPlugins</a></code>
</p>

Specifies the Remark plugins to use with the Markdown processor.

#### `AstroMarkdownOptions.rehypePlugins`

<p>

**Type:** <code><a href="#rehypeplugins">RehypePlugins</a></code>
</p>

Specifies the Rehype plugins to use with the Markdown processor.

#### `AstroMarkdownOptions.remarkRehype`

<p>

**Type:** <code><a href="#remarkrehype">RemarkRehype</a></code>
</p>

Specifies the [`remark-rehype` configuration](https://github.com/remarkjs/remark-rehype#options) to use with the Markdown processor.

### `MarkdownHeading`

<p>

**Type:** `{ depth: number; slug: string; text: string; }`<br />
<Since v="7.2.0" pkg="@astrojs/markdown-remark" />
</p>

Represents a heading in a Markdown or MDX document.

#### `MarkdownHeading.depth`

<p>

**Type:** `number`
</p>

Specifies the heading level, from `1` (`<h1>`) to `6` (`<h6>`).

#### `MarkdownHeading.slug`

<p>

**Type:** `string`
</p>

Specifies the generated slug used as the `id` attribute for anchor links.

#### `MarkdownHeading.text`

<p>

**Type:** `string`
</p>

Specifies the heading's rendered text content.

### `MarkdownProcessor`

<p>

**Type:** `object`<br />
<Since v="7.2.0" pkg="@astrojs/markdown-remark" />
</p>

Describes the interface implemented by a Markdown processor. This is useful when you want to indicate that a variable accepts any [built-in Markdown processor](/en/guides/markdown-content/#markdown-processors).

### `MarkdownRenderOptions`

<p>

**Type:** `{ fileURL?: URL; frontmatter?: Record<string, any>; }`<br />
<Since v="7.2.0" pkg="@astrojs/markdown-remark" />
</p>

Specifies the options available when rendering Markdown content.

#### `MarkdownRenderOptions.fileURL`

<p>

**Type:** `URL`
</p>

Specifies the URL of the Markdown file being rendered.

#### `MarkdownRenderOptions.frontmatter`

<p>

**Type:** `Record<string, any>`
</p>

Specifies the frontmatter data extracted from the Markdown file.

### `MarkdownRenderResult`

<p>

**Type:** <code>\{ code: string; metadata: \{ headings: <a href="#markdownheading">MarkdownHeading</a>[]; localImagePaths: string[]; remoteImagePaths: string[]; frontmatter: Record\<string, any\>; \}; \}</code><br />

</p>

#### `MarkdownRenderResult.metadata`

<p>

**Type:** <code>\{ headings: <a href="#markdownheading">MarkdownHeading</a>[]; localImagePaths: string[]; remoteImagePaths: string[]; frontmatter: Record\<string, any\>; \}</code>
</p>

Specifies the metadata associated with the rendered content.

##### `MarkdownRenderResult.metadata.headings`

<p>

**Type:** <code><a href="#markdownheading">MarkdownHeading</a>[]</code>
</p>

Specifies the headings extracted from the rendered content.

##### `MarkdownRenderResult.metadata.localImagePaths`

<p>

**Type:** `string[]`
</p>

Specifies the local image paths referenced in the rendered content.

##### `MarkdownRenderResult.metadata.remoteImagePaths`

<p>

**Type:** `string[]`
</p>

Specifies the remote image paths referenced in the rendered content.

##### `MarkdownRenderResult.metadata.frontmatter`

<p>

**Type:** `Record<string, any>`
</p>

Specifies the frontmatter data extracted from the rendered content.
