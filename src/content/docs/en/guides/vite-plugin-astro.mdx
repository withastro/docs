`@astrojs/vite-plugin-astro` lets you use [Astro components](/en/basics/astro-components/) in any Vite project, without an Astro project around them. Your own server decides what to render: a [Hono](https://hono.dev/) route, an Express handler, or a worker's `fetch()` renders a component and returns the HTML.

Components work as they do in Astro: scoped styles, `<script>` tags, and [islands](/en/concepts/islands/) of React, Preact, Solid, Svelte, or Vue components that hydrate in the browser.

:::caution[Experimental]
`@astrojs/vite-plugin-astro` and `@astrojs/runtime` are experimental. Their APIs may change in any minor release until they reach 1.0.
:::

## Installation

Install the plugin and the runtime:

<PackageManagerTabs>
  <Fragment slot="npm">
  ```shell
  npm install @astrojs/vite-plugin-astro @astrojs/runtime
  ```
  </Fragment>
  <Fragment slot="pnpm">
  ```shell
  pnpm add @astrojs/vite-plugin-astro @astrojs/runtime
  ```
  </Fragment>
  <Fragment slot="yarn">
  ```shell
  yarn add @astrojs/vite-plugin-astro @astrojs/runtime
  ```
  </Fragment>
</PackageManagerTabs>

Then add the plugin to your Vite config:

```js title="vite.config.js"
import astro from '@astrojs/vite-plugin-astro';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [astro()],
});
```

You can now import `.astro` files from your server code.

## Rendering a component

Import a component and render it with `renderToResponse()` or `renderToString()` from `@astrojs/runtime`:

```ts title="src/app.ts"
import { renderToResponse } from '@astrojs/runtime';
import { Hono } from 'hono';
import Page from './components/Page.astro';

const app = new Hono();

app.get('/hello/:name', (c) =>
  renderToResponse(Page, { props: { name: c.req.param('name') } }),
);

export default app;
```

```astro title="src/components/Page.astro"
---
const { name } = Astro.props;
---
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <title>Hello, {name}</title>
  </head>
  <body>
    <h1>Hello, {name}!</h1>
  </body>
</html>

<style>
  h1 { color: rebeccapurple; }
</style>
```

`renderToResponse()` returns a `Response` with a `Content-Type: text/html` header. `renderToString()` returns the HTML as a string.

By default, the result is a full HTML document: `<!DOCTYPE html>` is added, and the stylesheets of the component and its children are added to the `<head>`. To render part of a page, such as a fragment for [htmx](https://htmx.org/) or a component inside a page your server renders some other way, pass `partial: true`:

```ts
const html = await renderToString(Card, { props: { title: 'Hello' }, partial: true });
```

Rendering happens on the server only: call these functions from server code that Vite loads, not from code that runs in the browser.

## Adding islands

To render components from a UI framework, pass its renderer to `astro()` and add the framework's own Vite plugin. For React:

<PackageManagerTabs>
  <Fragment slot="npm">
  ```shell
  npm install @astrojs/react @vitejs/plugin-react react react-dom
  ```
  </Fragment>
  <Fragment slot="pnpm">
  ```shell
  pnpm add @astrojs/react @vitejs/plugin-react react react-dom
  ```
  </Fragment>
  <Fragment slot="yarn">
  ```shell
  yarn add @astrojs/react @vitejs/plugin-react react react-dom
  ```
  </Fragment>
</PackageManagerTabs>

```js title="vite.config.js" ins={1,3,7}
import react from '@astrojs/react/renderer';
import astro from '@astrojs/vite-plugin-astro';
import viteReact from '@vitejs/plugin-react';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [astro({ renderers: [react()] }), viteReact()],
});
```

The renderer tells Astro how to render and hydrate the framework's components. The framework's Vite plugin compiles its files, as it would in any Vite project.

Components can then be used with any [client directive](/en/reference/directives-reference/#client-directives):

```astro title="src/components/Page.astro" ins={2,7}
---
import Counter from './Counter.tsx';
const { name } = Astro.props;
---
<body>
  <h1>Hello, {name}!</h1>
  <Counter client:load />
</body>
```

The rendered HTML includes everything needed to hydrate the island: you don't need to add any scripts yourself.

Each framework package exports its renderer from `/renderer`:

| Framework | Renderer | Vite plugin |
| --- | --- | --- |
| React | `react()` from `@astrojs/react/renderer` | `@vitejs/plugin-react` |
| Preact | `preact()` from `@astrojs/preact/renderer` | `@preact/preset-vite` |
| Solid | `solid()` from `@astrojs/solid-js/renderer` | `vite-plugin-solid`, with `ssr: true` |
| Svelte | `svelte()` from `@astrojs/svelte/renderer` | `@sveltejs/vite-plugin-svelte` |
| Vue | `vue()` from `@astrojs/vue/renderer` | `@vitejs/plugin-vue` |

The order of the plugins doesn't matter. To use several JSX frameworks together (for example, React and Preact), pass an `include` option to each renderer and to each framework's Vite plugin, so that each one handles only its own files, as you would with [their integrations](/en/guides/integrations-guide/react/#combining-multiple-jsx-frameworks).

<ReadMore>See [Framework components](/en/guides/framework-components/) for how to use framework components in Astro components. In a Vite project, skip the `astro add` step: add the renderer and the Vite plugin as shown above instead.</ReadMore>

## Developing

In development, load your server code through Vite's dev server so that Vite compiles your components when they are requested, and serves the client code of your islands. With Hono and Node.js:

```js title="dev.mjs"
import { createServer as createHttpServer } from 'node:http';
import { getRequestListener } from '@hono/node-server';
import { createServer } from 'vite';

const vite = await createServer({ server: { middlewareMode: true }, appType: 'custom' });

const listener = getRequestListener(async (request) => {
  const { default: app } = await vite.ssrLoadModule('/src/app.ts');
  return app.fetch(request);
});

createHttpServer((req, res) => vite.middlewares(req, res, () => listener(req, res))).listen(3000);
```

Editing a component updates the page in the browser: style changes are applied without a reload, and other changes reload the page.

If your platform or framework has its own Vite plugin that runs your server in development (for example, `@cloudflare/vite-plugin`), use that instead.

## Building

Tell Vite where your server code starts with the build input of the `ssr` environment. Optionally, choose where each build is written:

```js title="vite.config.js" ins={6-14}
import astro from '@astrojs/vite-plugin-astro';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [astro()],
  environments: {
    ssr: {
      build: {
        outDir: 'dist/server',
        rolldownOptions: { input: { app: 'src/app.ts' } },
      },
    },
    client: { build: { outDir: 'dist/client' } },
  },
});
```

`vite build` then builds your server code to `dist/server/`, and the browser code of your components to `dist/client/`: the stylesheets, the islands, the framework's client code, and the components' `<script>` tags. The rendered HTML links to these files.

Your server must serve `dist/client/` as static files. With Hono and Node.js:

```js title="start.mjs"
import { serve } from '@hono/node-server';
import { serveStatic } from '@hono/node-server/serve-static';
import { Hono } from 'hono';
import app from './dist/server/app.js';

const server = new Hono();
server.use('/assets/*', serveStatic({ root: './dist/client' }));
server.route('/', app);

serve({ fetch: server.fetch, port: 3000 });
```

Hosting platforms that deploy a Vite project's client output as static assets do this for you.

## The `Astro` global

In a component rendered by `renderToResponse()` or `renderToString()`, the [`Astro` global](/en/reference/api-reference/) has the properties that only depend on the component and the render call:

| Property | Value |
| --- | --- |
| `Astro.props` | The `props` passed to the render function, or by the parent component. |
| `Astro.slots` | The component's [slots](/en/basics/astro-components/#slots). |
| `Astro.self` | The component itself, for [recursive components](/en/reference/astro-syntax/#astroself). |
| `Astro.request` | The `request` passed to the render function. Defaults to a `GET` request for `http://localhost/`. |
| `Astro.url` | The URL of `Astro.request`. |
| `Astro.site` | The `site` option of `astro()`, as a `URL`. |
| `Astro.generator` | The Astro version. |

To make request data available to a component, pass the request, or pass the data as props:

```ts
app.get('/profile', async (c) => {
  const user = await getUser(c);
  return renderToResponse(Profile, { request: c.req.raw, props: { user } });
});
```

## Limitations

The following Astro features are available in Astro projects, and not in components rendered with `@astrojs/vite-plugin-astro`:

- Pages and routing: `src/pages/`, `getStaticPaths()`, and prerendering. Your server decides which component to render for each request.
- Request-level APIs: `Astro.cookies`, `Astro.params`, `Astro.redirect()`, `Astro.locals`, [actions](/en/guides/actions/), [sessions](/en/guides/sessions/), and [internationalization](/en/guides/internationalization/) helpers.
- [Server islands](/en/guides/server-islands/) (`server:defer`).
- [View transitions](/en/guides/view-transitions/) (`<ClientRouter />`).
- Astro's built-in modules, such as `astro:assets`, `astro:content`, and `astro:env`.
- [Content Security Policy](/en/reference/configuration-reference/#securitycsp), inlining of scripts and stylesheets, and `build.assetsPrefix`.
- Integrations. Use Vite plugins instead.

Stylesheets are always linked in production, and scoped styles use the `attribute` [strategy](/en/reference/configuration-reference/#scopedstylestrategy).

## TypeScript

To import `.astro` files from TypeScript, declare their type:

```ts title="src/env.d.ts"
declare module '*.astro' {
  import type { AstroComponentFactory } from '@astrojs/runtime/types';
  const Component: AstroComponentFactory;
  export default Component;
}
```

## Reference

### `astro()` options

```js
astro({
  site: 'https://example.com',
  renderers: [react()],
});
```

All options are optional.

#### `site`

**Type:** `string`

The URL your site is deployed to, available as `Astro.site`.

#### `renderers`

**Type:** `AstroRenderer[]`<br />
**Default:** `[]`

The renderers of the UI frameworks your components use. When a component could be handled by more than one renderer, they are tried in this order.

#### `clientDirectives`

**Type:** `{ name: string; entrypoint: string | URL }[]`<br />
**Default:** `[]`

[Custom client directives](/en/reference/directives-reference/#custom-client-directives), in the same shape as the integration API's `addClientDirective()`.

#### `compressHTML`

**Type:** `boolean | 'jsx'`<br />
**Default:** `'jsx'`

How whitespace in component templates is compressed. See [`compressHTML`](/en/reference/configuration-reference/#compresshtml).

#### `trailingSlash`

**Type:** `'always' | 'never' | 'ignore'`<br />
**Default:** `'ignore'`

See [`trailingSlash`](/en/reference/configuration-reference/#trailingslash).

#### `publicDir`

**Type:** `string`<br />
**Default:** `'./public'`

The directory of files served as-is, relative to `root`. A `<script src>` that points to a file in this directory must use [`is:inline`](/en/reference/directives-reference/#isinline).

#### `root`

**Type:** `string`<br />
**Default:** Vite's `root`

The project root, relative to Vite's `root`.

The base URL is Vite's [`base`](https://vite.dev/config/shared-options.html#base): `astro()` has no `base` option.

### `renderToResponse()` and `renderToString()`

```ts
function renderToResponse(Component, options?: RenderOptions): Promise<Response>;
function renderToString(Component, options?: RenderOptions): Promise<string>;
```

#### `props`

**Type:** `Record<string, any>`<br />
**Default:** `{}`

The component's props, available as `Astro.props`.

#### `slots`

**Type:** `Record<string, string>`<br />
**Default:** `{}`

HTML for each slot, by slot name. Use `default` for the default slot.

#### `request`

**Type:** `Request`<br />
**Default:** a `GET` request for `http://localhost/`

Available as `Astro.request` and `Astro.url`.

#### `partial`

**Type:** `boolean`<br />
**Default:** `false`

When `false`, renders a full document: `<!DOCTYPE html>` is added, and the stylesheets of the component tree are added to the `<head>`. When `true`, renders the component's HTML only.
