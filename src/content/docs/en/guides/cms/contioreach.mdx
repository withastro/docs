[ContioReach](https://contioreach.com/) is a headless CMS built specifically for blogs. Posts, authors, categories, and tags are modeled out of the box and delivered as JSON over a REST API that you can fetch from your Astro project.

## Features

- **Ready-made blog content model**: posts, authors, categories, tags, cover images, and SEO metadata are available without designing a schema first.
- **REST Content API**: fetch published posts as JSON with pagination and filters for category, tag, author, and keyword. There is no SDK to install.
- **Publish webhooks**: ContioReach sends a request to your site when a post is published, scheduled, edited, or deleted, so you can invalidate a cache or trigger a rebuild.
- **Works with static and on-demand rendering**: prerender your blog at build time with `getStaticPaths()`, or render on demand with an adapter.
- **Editorial tools**: a writing editor, scheduling, SEO guidance, and internal linking suggestions for the people writing your content.
- **Workspaces**: keep separate blogs, teams, and API keys under one account.

## Integrating with Astro

In this guide, you will fetch your published posts from the ContioReach Content API in your Astro project, then build a blog index page and a page for each post.

The Content API is a read-only REST API that returns JSON, so you can use `fetch()` without installing any packages.

## Prerequisites

To get started, you will need to have the following:

- **An Astro project** - If you don't have an Astro project yet, you can follow the instructions in our [Installation guide](/en/install-and-setup/).
- **A ContioReach account and workspace** - If you don't have an account, you can [sign up for a free account](https://app.contioreach.com/signup).
- **The API key for your ContioReach workspace** - You can find it in your workspace under "Developer Settings" > "API Keys".
- **At least one published post** - The Content API only returns published posts, not drafts.

## Setting up the credentials

Create a new file (if one does not already exist) named `.env` in the root of your Astro project. Add the following environment variables, using the API key found in your ContioReach workspace:

```ini title=".env"
CMS_API_URL=https://cms-api.contioreach.com
CMS_API_KEY=YOUR_API_KEY
```

:::caution
Do not prefix the API key with `PUBLIC_`. Variables with that prefix are available in client-side code, and your API key must stay on the server.
:::

For TypeScript support, declare the typing of these environment variables in the `env.d.ts` file in the `src/` folder. If this file does not exist, you can create it and add the following:

```ts title="src/env.d.ts"
interface ImportMetaEnv {
	readonly CMS_API_URL: string;
	readonly CMS_API_KEY: string;
}
```

Your root directory should now include these files:

<FileTree title="Project Structure">
- src/
  - **env.d.ts**
- **.env**
- astro.config.mjs
- package.json
</FileTree>

<ReadMore>Learn more about [environment variables](/en/guides/environment-variables/) and `.env` files in Astro.</ReadMore>

## Fetching data

Every request to the Content API is authenticated by sending your API key in an `X-API-Key` header.

Create a new file `src/lib/contioreach.ts` with helper functions to request a page of posts, and a single post by its slug:

```ts title="src/lib/contioreach.ts"
async function apiRequest(endpoint: string) {
	const response = await fetch(`${import.meta.env.CMS_API_URL}${endpoint}`, {
		headers: {
			'X-API-Key': import.meta.env.CMS_API_KEY,
		},
	});

	// The API responds with a 404 status when no post matches a slug.
	if (response.status === 404) {
		return { data: null };
	}

	if (!response.ok) {
		throw new Error(`ContioReach request failed: ${response.status}`);
	}

	return response.json();
}

export function getPosts(page = 1, limit = 100) {
	return apiRequest(`/v1/blogs?page=${page}&limit=${limit}&minimal=true`);
}

export async function getPost(slug: string) {
	// minimal=false includes the full HTML body of the post.
	const { data } = await apiRequest(`/v1/blogs?slug=${slug}&minimal=false`);
	return data;
}
```

A request for a list of posts returns a `data` array and a `meta` object with pagination details. Each post includes properties such as:

- `title` - The title of the post.
- `slug` - The URL-friendly identifier of the post.
- `excerpt` - A short summary to show on listing pages.
- `coverImage` and `coverImageAlt` - The URL and alt text of the cover image.
- `publishedAt` - The date the post was published.
- `authors`, `categories`, and `tags` - Arrays of the related items.

A request for a single post by its slug returns one object in `data`. With `minimal=false`, it also includes `content`, the body of the post as HTML.

<ReadMore>See every query parameter and response field in the [ContioReach Posts API reference](https://contioreach.com/docs/api/posts).</ReadMore>

## Making a blog with ContioReach and Astro

With the setup above, you can now create a blog that uses ContioReach as the CMS. The blog will have these pages:

<FileTree title="Project Structure">
- src/
  - lib/
    - contioreach.ts
  - pages/
    - blog/
      - **index.astro**
      - **[slug].astro**
- astro.config.mjs
- package.json
</FileTree>

### Displaying a list of posts

Create the page `src/pages/blog/index.astro` to list your posts, each with a link to its own page:

```astro title="src/pages/blog/index.astro"
---
import { getPosts } from '../../lib/contioreach';

const { data: posts } = await getPosts(1, 12);
---

<html lang="en">
	<head>
		<title>Blog</title>
	</head>
	<body>
		<h1>Blog</h1>
		<ul>
			{
				posts.map((post: any) => (
					<li>
						<a href={`/blog/${post.slug}/`}>{post.title}</a>
						<p>{post.excerpt}</p>
					</li>
				))
			}
		</ul>
	</body>
</html>
```

### Generating a page for each post

Create the page `src/pages/blog/[slug].astro` to [dynamically generate a page](/en/guides/routing/#dynamic-routes) for each post.

The Content API returns up to 100 posts per request, so `getStaticPaths()` requests each page of results until `meta.hasNextPage` is `false`:

```astro title="src/pages/blog/[slug].astro"
---
import { getPost, getPosts } from '../../lib/contioreach';

// getStaticPaths() is required for static Astro sites.
// If using on-demand rendering, you will not need this function.
export async function getStaticPaths() {
	const posts = [];
	let page = 1;
	let hasNextPage = true;

	while (hasNextPage) {
		const { data, meta } = await getPosts(page);
		posts.push(...data);
		hasNextPage = meta.hasNextPage;
		page += 1;
	}

	return posts.map((post: any) => ({
		params: { slug: post.slug },
	}));
}

const { slug } = Astro.params;
const post = await getPost(slug);
---

<html lang="en">
	<head>
		<title>{post.metaTitle}</title>
		<meta name="description" content={post.description} />
	</head>
	<body>
		<article>
			<h1>{post.title}</h1>
			{post.coverImage && <img src={post.coverImage} alt={post.coverImageAlt} />}
			<Fragment set:html={post.content} />
		</article>
	</body>
</html>
```

:::note
The `set:html` directive does not escape the HTML it renders. This is intended for the body of a post written by your own authors.
:::

### Using on-demand rendering

If you have [enabled on-demand rendering with an adapter](/en/guides/on-demand-rendering/), remove `getStaticPaths()` from `src/pages/blog/[slug].astro` and return a 404 response when a post is not found:

```astro title="src/pages/blog/[slug].astro"
---
import { getPost } from '../../lib/contioreach';

const { slug } = Astro.params;
const post = await getPost(slug!);

if (!post) {
	return new Response(null, { status: 404, statusText: 'Not found' });
}
---
```

## Publishing your site

To deploy your website, visit our [deployment guides](/en/guides/deploy/) and follow the instructions for your preferred hosting provider.

Add `CMS_API_URL` and `CMS_API_KEY` to the environment variables of your hosting provider so that they are available when your site is built.

## Publish on ContioReach content changes

If your project is using Astro's default static mode, you will need to set up a webhook to trigger a new build when your content changes. If you are using Netlify or Vercel as your hosting provider, you can use its webhook feature to trigger a new build when you change content in ContioReach.

ContioReach sends a webhook when a post is published, scheduled, edited after publishing, or deleted. Saving a draft does not send one.

### Netlify

To set up a webhook in Netlify:

<Steps>
1. Go to your site dashboard and click on **Build & deploy**.

2. Under the **Continuous Deployment** tab, find the **Build hooks** section and click on **Add build hook**.

3. Provide a name for your webhook and select the branch you want to trigger the build on. Click on **Save** and copy the generated URL.
</Steps>

### Vercel

To set up a webhook in Vercel:

<Steps>
1. Go to your project dashboard and click on **Settings**.

2. Under the **Git** tab, find the **Deploy Hooks** section.

3. Provide a name for your webhook and the branch you want to trigger the build on. Click **Add** and copy the generated URL.
</Steps>

### Adding a webhook to ContioReach

<Steps>
1. In your ContioReach workspace, open **Developer Settings** and select **Webhook Integration**.

2. In the URL field, paste the URL generated by your preferred hosting service.

3. Generate a secure token and save the webhook configuration.
</Steps>

If your site is rendered on demand, you can instead point the webhook at an [endpoint](/en/guides/endpoints/#server-endpoints-api-routes) in your project. ContioReach sends the token you generated in an `X-API-Key` header, so your endpoint can verify the request before updating any cached content.

<ReadMore>Read more about the webhook request and its payload in the [ContioReach webhooks documentation](https://contioreach.com/docs/webhooks).</ReadMore>
