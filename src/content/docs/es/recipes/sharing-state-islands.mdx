Al construir un sitio web de Astro con [arquitectura de islas / hidratación parcial](/es/concepts/islands/), es posible que te hayas encontrado con este problema: **Quiero compartir el estado entre mis componentes.**

Los frameworks de interfaz de usuario como React o Vue pueden fomentar los [proveedores de "contexto"](https://react.dev/learn/passing-data-deeply-with-context) para que otros componentes los consuman. Pero al [hidratar parcialmente componentes](/es/guides/framework-components/#hidratación-de-componentes-interactivos) dentro de Astro o Markdown, no puedes usar estos envoltorios de contexto.

Astro recomienda una solución diferente para el almacenamiento compartido del lado del cliente: [**Nano Stores**](https://github.com/nanostores/nanostores).

<RecipeLinks slugs={["es/recipes/sharing-state"]} />

## ¿Por qué Nano Stores?

La biblioteca [Nano Stores](https://github.com/nanostores/nanostores) te permite crear stores con las que cualquier componente puede interactuar. Recomendamos Nano Stores porque:
- **Son ligeras.** Nano Stores envían el mínimo indispensable de JS que necesitarás (menos de 1 KB) sin dependencias.
- **Son agnósticas al framework.** ¡Esto significa que compartir el estado entre frameworks será fluido! Astro se basa en la flexibilidad, por lo que nos encantan las soluciones que ofrecen una experiencia de desarrollo similar sin importar tu preferencia.

Aun así, hay varias alternativas que puedes explorar. Estas incluyen:
- [Stores integradas de Svelte](https://svelte.dev/docs/svelte/stores)
- [Signals de Solid](https://docs.solidjs.com/reference/basic-reactivity/create-signal) fuera del contexto de un componente
- [API de reactividad de Vue](https://vuejs.org/guide/scaling-up/state-management.html#simple-state-management-with-reactivity-api)
- [Enviar eventos personalizados del navegador](https://developer.mozilla.org/es/docs/Web/Events/Creating_and_triggering_events) entre componentes

:::note[Preguntas frecuentes]

<details>
<summary>**🙋 ¿Puedo usar Nano Stores en archivos `.astro` u otros componentes del lado del servidor?**</summary>

Las Nano Stores se pueden usar en etiquetas `<script>` para [compartir el estado entre componentes `.astro`](/es/recipes/sharing-state/). Sin embargo, no se recomienda usar Nano Stores en el frontmatter de componentes del lado del servidor debido a las siguientes restricciones:
- Escribir en una store desde un archivo `.astro` o [componente no hidratado](/es/guides/framework-components/#hidratación-de-componentes-interactivos) _no_ afectará el valor recibido por los [componentes del lado del cliente](/es/reference/directives-reference/#directivas-del-cliente).
- No puedes pasar una Nano Store como una "prop" a componentes del lado del cliente.
- No puedes suscribirte a los cambios de la store desde un archivo `.astro`, ya que los componentes de Astro no se vuelven a renderizar.

Si entiendes estas restricciones y aún encuentras un caso de uso, ¡puedes probar Nano Stores! Solo recuerda que Nano Stores están diseñadas para la reactividad ante cambios en el **cliente** específicamente.

</details>

<details>
<summary>**🙋 ¿Cómo se comparan las stores de Svelte con Nano Stores?**</summary>

**¡Nano Stores y las [stores de Svelte](https://svelte.dev/docs/svelte/stores) son muy similares!** De hecho, [nanostores te permiten usar el mismo atajo `$`](https://github.com/nanostores/nanostores#svelte) para suscripciones que usarías con las stores de Svelte.

Si quieres evitar bibliotecas de terceros, las [stores de Svelte](https://svelte.dev/docs/svelte/stores) son una excelente herramienta de comunicación entre islas por sí mismas. Aun así, podrías preferir Nano Stores si a) te gustan sus complementos para ["objetos"](https://github.com/nanostores/nanostores#maps) y [estado asíncrono](https://github.com/nanostores/nanostores#lazy-stores), o b) quieres comunicarte entre Svelte y otros frameworks de interfaz de usuario como Preact o Vue.
</details>

<details>
<summary>**🙋 ¿Cómo se comparan las signals de Solid con Nano Stores?**</summary>

Si has usado Solid por un tiempo, es posible que hayas intentado mover [signals](https://www.solidjs.com/docs/latest#createsignal) o [stores](https://www.solidjs.com/docs/latest#createstore) fuera de tus componentes. ¡Esta es una excelente manera de compartir el estado entre islas de Solid! Intenta exportar signals desde un archivo compartido:

```js
// sharedStore.js
import { createSignal } from 'solid-js';

export const sharedCount = createSignal(0);
```
...y todos los componentes que importen `sharedCount` compartirán el mismo estado. Aunque esto funciona bien, podrías preferir Nano Stores si a) te gustan sus complementos para ["objetos"](https://github.com/nanostores/nanostores#maps) y [estado asíncrono](https://github.com/nanostores/nanostores#lazy-stores), o b) quieres comunicarte entre Solid y otros frameworks de interfaz de usuario como Preact o Vue.
</details>
:::

### Usando "atoms"

Comencemos abriendo nuestro `CartFlyout` cada vez que se haga clic en `CartFlyoutToggle`. 

Primero, crea un nuevo archivo JS o TS para que contenga nuestra store. Usaremos un ["atom"](https://github.com/nanostores/nanostores#atoms) para esto:

```js
// src/cartStore.js
import { atom } from 'nanostores';

export const isCartOpen = atom(false);
```

Ahora, podemos importar esta store en cualquier archivo que necesite leer o escribir. Comenzaremos conectando nuestro `CartFlyoutToggle`:

### Usando "maps"

:::tip
**¡Los [maps](https://github.com/nanostores/nanostores#maps) son una excelente opción para objetos en los que escribes regularmente!** Junto a las funciones auxiliares estándar `get()` y `set()` que proporciona un `atom`, también tendrás una función `.setKey()` para actualizar eficientemente claves de objetos individuales.
:::

Ahora, hagamos un seguimiento de los artículos dentro de tu carrito. Para evitar duplicados y hacer un seguimiento de la "cantidad", podemos almacenar tu carrito como un objeto con el ID del artículo como clave. Usaremos un [Map](https://github.com/nanostores/nanostores#maps) para esto.

Agreguemos una store `cartItem` a nuestro `cartStore.js` de antes. También puedes cambiar a un archivo TypeScript para definir la estructura si así lo deseas.

<JavascriptFlavorTabs>
  <Fragment slot="js">
  ```js
  // src/cartStore.js
  import { atom, map } from 'nanostores';

  export const isCartOpen = atom(false);

  /**
   * @typedef {Object} CartItem
   * @property {string} id
   * @property {string} name
   * @property {string} imageSrc
   * @property {number} quantity
   */

  /** @type {import('nanostores').MapStore<Record<string, CartItem>>} */
  export const cartItems = map({});

  ```
  </Fragment>
  <Fragment slot="ts">
  ```ts
  // src/cartStore.ts
  import { atom, map } from 'nanostores';

  export const isCartOpen = atom(false);

  export type CartItem = {
    id: string;
    name: string;
    imageSrc: string;
    quantity: number;
  }

  export const cartItems = map<Record<string, CartItem>>({});
  ```
  </Fragment>
</JavascriptFlavorTabs>

Ahora, exportemos una función auxiliar `addCartItem` para que la usen nuestros componentes.
- **Si ese artículo no existe en tu carrito**, agrega el artículo con una cantidad inicial de 1.
- **Si ese artículo _ya_ existe**, incrementa la cantidad en 1.

<JavascriptFlavorTabs>
  <Fragment slot="js">
  ```js
  // src/cartStore.js
  ...
  export function addCartItem({ id, name, imageSrc }) {
    const existingEntry = cartItems.get()[id];
    if (existingEntry) {
      cartItems.setKey(id, {
        ...existingEntry,
        quantity: existingEntry.quantity + 1,
      })
    } else {
      cartItems.setKey(
        id,
        { id, name, imageSrc, quantity: 1 }
      );
    }
  }
  ```
  </Fragment>
  <Fragment slot="ts">

:::note
<details>

<summary>**🙋 ¿Por qué usar `.get()` aquí en lugar de un helper `useStore`?**</summary>

Es posible que hayas notado que estamos llamando a `cartItems.get()` aquí, en lugar de tomar ese asistente `useStore` de nuestros ejemplos de React / Preact / Solid / Vue. Esto se debe a que **useStore está pensado para desencadenar re-renderizados de componentes.** En otras palabras, `useStore` debe usarse cada vez que el valor de la store se renderiza en la interfaz de usuario. Dado que estamos leyendo el valor cuando se desencadena un **evento** (`addToCart` en este caso), y no estamos intentando renderizar ese valor, no necesitamos `useStore` aquí.
</details>
:::

```jsx
import { isCartOpen, cartItems } from '../cartStore';

export default function CartFlyout() {
  const $isCartOpen = useStore(isCartOpen);
  const $cartItems = useStore(cartItems);

  return $isCartOpen ? (
    <aside>
      {Object.values($cartItems).length ? (
        <ul>
          {Object.values($cartItems).map(cartItem => (
            <li>

            </li>
          ))}
        </ul>
      ) : <p>Your cart is empty!</p>}
    </aside>
  ) : null;
}
```
