Para ayudar a algunos usuarios a migrar entre versiones de Astro, ocasionalmente introducimos banderas `legacy`.

Estas banderas te permiten optar por un comportamiento obsoleto o desactualizado de Astro en la última versión, para que puedas seguir actualizando y aprovechando las nuevas versiones de Astro hasta que puedas actualizar completamente el código de tu proyecto.

## collectionsBackwardsCompat

<p>

**Tipo:** `boolean`<br />
**Predeterminado:** `false`<br />
<Since v="6.0.0" />
</p>

Proporciona compatibilidad con versiones anteriores de forma temporal para proyectos que no pueden migrar a la API de Content Layer introducida en v5.0.

```js
// astro.config.mjs
import { defineConfig } from "astro/config";

export default defineConfig({
  legacy: {
    collectionsBackwardsCompat: true,
  },
});
```

Cuando está habilitado, conserva las siguientes características de colecciones de contenido heredadas de v4:

- Permite la ubicación heredada del archivo de configuración: `src/content/config.ts`
- Permite colecciones sin loaders explícitos (se envuelve automáticamente con el loader glob)
- Admite `type: 'content'` y `type: 'data'` sin loaders
- Conserva la API de entrada heredada: `entry.slug` y `entry.render()`
- Utiliza IDs de entrada basados en rutas en lugar de IDs basados en slugs

Este es un asistente de migración temporal. Migra las colecciones a la API de Content Layer y luego deshabilita esta opción.
