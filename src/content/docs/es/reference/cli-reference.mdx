Puedes usar la Interfaz de Línea de Comandos (CLI) provista por Astro para desarrollar, compilar y obtener una vista previa de tu proyecto desde una ventana de terminal.

### Comandos de `astro`

Usa la CLI ejecutando uno de los **comandos** documentados en esta página con tu gestor de paquetes preferido, seguido opcionalmente de cualquiera de las **banderas**. Las banderas personalizan el comportamiento de un comando.

Uno de los comandos que usarás con más frecuencia es `astro dev`. Este comando inicia el servidor de desarrollo y te ofrece una vista previa en vivo y actualizada de tu sitio en el navegador mientras trabajas:


### Scripts en `package.json`

También puedes usar scripts en `package.json` para versiones más cortas de estos comandos. Usar un script te permite utilizar los mismos comandos con los que quizás ya estés familiarizado en otros proyectos, como `npm run build`.

Los siguientes scripts para los comandos más comunes de `astro` (`astro dev`, `astro build` y `astro preview`) se añaden automáticamente cuando creas un proyecto utilizando [el asistente `create astro`](/es/install-and-setup/).

Cuando sigues las instrucciones para [instalar Astro manualmente](/es/install-and-setup/#configuración-manual), se te indica que añadas estos scripts tú mismo. También puedes añadir manualmente más scripts a esta lista para cualquier comando que uses con frecuencia.

```json title="package.json"
{
  "scripts": {
    "dev": "astro dev",
    "build": "astro build",
    "preview": "astro preview"
  }
}
```

A menudo usarás estos comandos de `astro`, o los scripts que los ejecutan, sin ninguna bandera. Añade banderas al comando cuando desees personalizar su comportamiento. Por ejemplo, es posible que quieras iniciar el servidor de desarrollo en un puerto diferente o compilar tu sitio con registros detallados para depuración.

## `astro dev`

Ejecuta el servidor de desarrollo de Astro. Este es un servidor HTTP local que no empaqueta recursos. Utiliza Hot Module Replacement (HMR) para actualizar tu navegador a medida que guardas los cambios en tu editor.

Los siguientes atajos de teclado se pueden utilizar en la terminal donde se está ejecutando el servidor de desarrollo de Astro:

- `s + enter` para sincronizar los datos de la capa de contenido (contenido y tipos).
- `o + enter` para abrir tu sitio de Astro en el navegador.
- `q + enter` para salir del servidor de desarrollo.

El comando se puede combinar con las [banderas comunes](#banderas-comunes) y los [subcomandos comunes](#subcomandos-comunes) para controlar aún más la experiencia de desarrollo.

## `astro build`

Compila tu sitio para producción. Por defecto, esto generará archivos estáticos y los colocará en un directorio `dist/`. Si alguna ruta se [renderiza bajo demanda](/es/guides/on-demand-rendering/), esto generará los archivos de servidor necesarios para servir tu sitio.

<h3>Banderas</h3>

El comando acepta [banderas comunes](#banderas-comunes) y las siguientes banderas adicionales:

#### `--devOutput`

<p><Since v="5.0.0" /></p>

Genera una compilación basada en desarrollo similar al código transformado en `astro dev`. Esto puede ser útil para probar problemas exclusivos de compilación con información de depuración adicional incluida.

#### `--timings`

<p><Since v="7.4.0" /></p>

Muestra un resumen de dónde dedicó su tiempo la compilación una vez que finaliza. El informe abarca las fases de compilación, los plugins de Vite, el procesamiento de Markdown y el resaltado de sintaxis, el renderizado de páginas, la optimización de imágenes y los hooks de integración.

## `astro preview`

Inicia un servidor local para servir el contenido de tu directorio estático (`dist/` por defecto) creado al ejecutar `astro build`.

Este comando te permite previsualizar tu sitio localmente [después de compilarlo](#astro-build) para detectar cualquier error en la salida de tu compilación antes de desplegarlo. No está diseñado para ejecutarse en producción. Para obtener ayuda con el alojamiento en producción, consulta nuestra guía sobre [Cómo desplegar un sitio web de Astro](/es/guides/deploy/).

Los siguientes atajos de teclado se pueden utilizar en la terminal donde se está ejecutando el servidor de vista previa de Astro:
- `o` + `enter` para abrir tu sitio de Astro en el navegador.
- `q` + `enter` para salir del servidor de vista previa.

El comando se puede combinar con las [banderas comunes](#banderas-comunes) y los [subcomandos comunes](#subcomandos-comunes) para controlar aún más la experiencia de vista previa.

## `astro check`

Ejecuta diagnósticos (como la verificación de tipos dentro de archivos `.astro`) en tu proyecto y reporta errores a la consola. Si se encuentra algún error, el proceso finalizará con un código de **1**.

Este comando está destinado a utilizarse en flujos de trabajo de CI.

<h3>Banderas</h3>

Usa estas banderas para personalizar el comportamiento del comando.

#### `--watch`

El comando observará cualquier cambio en tu proyecto y reportará cualquier error.

#### `--root <path-to-dir>`

Especifica un directorio raíz diferente para verificar. Usa el directorio de trabajo actual por defecto.

#### `--tsconfig <path-to-file>`

Especifica un archivo `tsconfig.json` para usar manualmente. Si no se proporciona, Astro intentará encontrar una configuración o inferir automáticamente la configuración del proyecto.

#### `--minimumFailingSeverity <error|warning|hint>`

Especifica la severidad mínima necesaria para finalizar con un código de error. Por defecto es `error`.

Por ejemplo, ejecutar `astro check --minimumFailingSeverity warning` hará que el comando finalice con un error si se detecta alguna advertencia.

#### `--minimumSeverity <error|warning|hint>`

Especifica la severidad mínima a mostrar en la salida. Por defecto es `hint`.

Por ejemplo, ejecutar `astro check --minimumSeverity warning` mostrará errores y advertencias, pero no sugerencias.

#### `--preserveWatchOutput`

Especifica no limpiar la salida entre comprobaciones cuando se está en modo de observación.

#### `--noSync`

Especifica no ejecutar `astro sync` antes de verificar el proyecto.

<ReadMore>Lee más sobre la [verificación de tipos en Astro](/es/guides/typescript/#verificación-de-tipos).</ReadMore>

## `astro sync`

<p><Since v="2.0.0" /></p>

:::tip
Ejecutar `astro dev`, `astro build` o `astro check` también ejecutará el comando `sync`.
:::

Genera tipos de TypeScript para todos los módulos de Astro. Esto configura un [archivo `.astro/types.d.ts`](/es/guides/typescript/#configuración) para la inferencia de tipos y define módulos para características que dependen de tipos generados:
- El módulo `astro:content` para la [API de colecciones de contenido](/es/guides/content-collections/).
- El módulo `astro:env` para [Astro Env](/es/guides/environment-variables/).
- El módulo `astro:actions` para [Astro Actions](/es/guides/actions/)

## `astro preferences`

Gestiona las preferencias de usuario con el comando `astro preferences`. Las preferencias de usuario son específicas de cada desarrollador individual de Astro, a diferencia del archivo `astro.config.mjs` que cambia el comportamiento para todos los que trabajan en un proyecto.

Las preferencias de usuario están delimitadas al proyecto actual por defecto, almacenadas en un archivo local `.astro/settings.json`.

Usando la bandera `--global`, las preferencias de usuario también se pueden aplicar a cada proyecto de Astro en la máquina actual. Las preferencias de usuario globales se almacenan en una ubicación específica del sistema operativo.

<h3>Preferencias disponibles</h3>

- `devToolbar` — Habilita o deshabilita la barra de herramientas de desarrollo en el navegador. (Por defecto: `true`)
- `checkUpdates` — Habilita o deshabilita las comprobaciones automáticas de actualizaciones para la CLI de Astro. (Por defecto: `true`)

El comando `list` imprime los ajustes actuales de todas las preferencias de usuario configurables. También admite una salida legible por máquina con `--json`.

```shell
astro preferences list
```

Salida de ejemplo en la terminal:

| Preferencia              | Valor |
| ------------------------ | ----- |
| devToolbar.enabled       | true  <tr></tr>|
| checkUpdates.enabled     | true  |


Puedes usar `enable`, `disable` o `reset` para modificar las preferencias a sus valores por defecto.

Por ejemplo, para deshabilitar la devToolbar en un proyecto de Astro específico:

```shell
astro preferences disable devToolbar
```

Para deshabilitar la devToolbar en todos los proyectos de Astro en la máquina actual:

```shell
astro preferences disable --global devToolbar
```

La devToolbar se puede habilitar más tarde con:

```shell
astro preferences enable devToolbar
```

El comando `reset` restablece una preferencia a su valor por defecto:

```shell
astro preferences reset devToolbar
```

## `astro telemetry`

Establece la configuración de telemetría para el usuario actual de la CLI. La telemetría consiste en datos anónimos que proporcionan al equipo de Astro información sobre qué características de Astro se utilizan con mayor frecuencia. Para obtener más información, consulta la [página de telemetría de Astro](https://astro.build/telemetry/).

La telemetría se puede deshabilitar con este comando de la CLI:

```shell
astro telemetry disable
```

La telemetría se puede volver a habilitar más tarde con:

```shell
astro telemetry enable
```

El comando `reset` restablece los datos de telemetría:

```shell
astro telemetry reset
```

:::tip[¿Deseas deshabilitar la telemetría en entornos de CI?]
Añade el comando `astro telemetry disable` a tus scripts de CI o establece la variable de entorno `ASTRO_TELEMETRY_DISABLED`.
:::

## `astro create-key`

Genera una clave para cifrar las props pasadas a server islands.

```shell
astro create-key
```

Establece esta clave como la variable de entorno `ASTRO_KEY` (por ejemplo, en un archivo `.env`) e inclúyela en tu CI/CD o en la configuración de compilación de tu proveedor de alojamiento cuando necesites [una clave de cifrado constante para tus server islands](/es/guides/server-islands/#reusing-the-encryption-key) para situaciones como despliegues continuos (rolling deployments), alojamiento multirregión o una CDN que almacene en caché páginas que contienen server islands.

## Subcomandos comunes

<p><Since v="7.0.0" /></p>

Los comandos [`astro dev`](#astro-dev) y, a partir de la versión v7.2.0, [`astro preview`](#astro-preview) aceptan los siguientes subcomandos para gestionar un [servidor en segundo plano](#--background).

### `stop`

Detiene un servidor en segundo plano en ejecución. Envía `SIGTERM` y espera hasta 5 segundos a que el servidor finalice de forma ordenada. Si el proceso sigue en ejecución después de eso, escala a `SIGKILL`.

### `status`

Comprueba si un servidor en segundo plano se está ejecutando y muestra su URL, PID y tiempo de actividad (uptime).

### `logs`

Muestra los registros de un servidor en segundo plano. Solo funciona cuando el servidor se inició con la [bandera `--background`](#--background), ya que los servidores en primer plano escriben los registros directamente en la terminal.

#### Banderas

##### `--follow` (`-f`)

Transmite la nueva salida de registros a medida que se escriben, similar a `tail -f`. Sin esta bandera, se imprime el contenido actual del archivo de registro y el comando finaliza.

## Banderas comunes

### `--root <path>`

Especifica la ruta a la raíz del proyecto. Si no se especifica, se asume que el directorio de trabajo actual es la raíz.

La raíz se utiliza para encontrar el archivo de configuración de Astro.

```shell
astro --root myRootFolder/myProjectFolder dev
```

### `--config <path>`

Especifica la ruta al archivo de configuración relativa a la raíz del proyecto. Por defecto es `astro.config.mjs`. Usa esto si utilizas un nombre diferente para tu archivo de configuración o si tienes tu archivo de configuración en otra carpeta.

```shell
astro --config config/astro.config.mjs dev
```

### `--force`

<p><Since v="5.0.0" /></p>

Limpia la caché de la capa de contenido, forzando una reconstrucción completa.

### `--mode <string>`

<p><Since v="5.0.0" /></p>

Configura la opción inline [`mode`](/es/reference/programmatic-reference/#astroinlineconfigmode) para tu proyecto.

### `--outDir <path>`

<p><Since v="3.3.0" /></p>

Configura [`outDir`](/es/reference/configuration-reference/#outdir) para tu proyecto. Pasar esta bandera anulará el valor de `outDir` en tu archivo `astro.config.mjs`, si existe uno.

### `--site <url>`

Configura [`site`](/es/reference/configuration-reference/#site) para tu proyecto. Pasar esta bandera anulará el valor de `site` en tu archivo `astro.config.mjs`, si existe uno.

### `--base <pathname>`

<p><Since v="1.4.1" /></p>

Configura [`base`](/es/reference/configuration-reference/#base) para tu proyecto. Pasar esta bandera anulará el valor de `base` en tu archivo `astro.config.mjs`, si existe uno.

### `--port <number>`

Especifica en qué puerto ejecutar el servidor de desarrollo y el servidor de vista previa. Por defecto es `4321`.

### `--host [optional host address]`

Establece en qué direcciones IP de red deben escuchar el servidor de desarrollo y el servidor de vista previa (es decir, IPs que no sean localhost). Esto puede ser útil para probar tu proyecto en dispositivos locales como un teléfono móvil durante el desarrollo.

- `--host` — escucha en todas las direcciones, incluidas direcciones LAN y públicas
- `--host <custom-address>` — expone en una dirección IP de red en `<custom-address>`

:::caution
No utilices la bandera `--host` para exponer el servidor de desarrollo y el servidor de vista previa en un entorno de producción. Los servidores están diseñados únicamente para uso local mientras desarrollas tu sitio.
:::

### `--allowed-hosts`

<p><Since v="5.4.0" /></p>

Especifica los nombres de host a los que Astro tiene permitido responder en los modos `dev` o `preview`. Se le puede pasar una lista de nombres de host separados por comas o `true` para permitir cualquier nombre de host.

Consulta la [característica `allowedHosts` de Vite](https://vite.dev/config/server-options.html#server-allowedhosts) para obtener más información, incluidas las implicaciones de seguridad al permitir nombres de host.

### `--verbose`

Habilita el registro detallado (verbose logging), lo cual es útil al depurar un problema.

### `--silent`

Habilita el registro silencioso (silent logging), lo cual ejecutará el servidor sin ninguna salida en la consola.

### `--open`

Abre automáticamente la aplicación en el navegador al iniciar el servidor. Se le puede pasar una cadena de URL completa (por ejemplo, `--open http://example.com`) o una ruta (por ejemplo, `--open /about`) para especificar la URL a abrir.

### `--background`

<p><Since v="7.0.0" /></p>

Inicia el servidor de desarrollo, o el servidor de vista previa a partir de v7.2.0, como un proceso en segundo plano separado y habilita el [registro en formato JSON](#--json).

Cuando el servidor se inicia, Astro escribe un archivo de bloqueo (`.astro/dev.json` o `.astro/preview.json`) para registrar la URL, el puerto y el PID del servidor. Esto evita iniciar múltiples instancias del servidor para el mismo proyecto.

Esta bandera se proporciona automáticamente cuando se detecta un agente de IA en macOS y Linux. En Windows, el paso automático a segundo plano no se produce: cuando se detecta un agente de IA, el servidor permanece en primer plano para que el agente pueda gestionar el proceso directamente. En todas las plataformas, también puedes usar la bandera manualmente:

```shell
astro dev --background
```

Si ya se está ejecutando un servidor para el proyecto, el comando imprime la información del servidor existente y sale sin iniciar uno nuevo. Usa la bandera `--force` para detener el servidor existente e iniciar uno nuevo.

```shell
astro dev --background --force
```

<ReadMore>Consulta [Modo en segundo plano para agentes de codificación con IA](/es/guides/build-with-ai/#modo-en-segundo-plano) para obtener más información sobre la detección automática de agentes y el health endpoint.</ReadMore>

### `--json`

<p><Since v="7.0.0" /></p>

Habilita el [registro en JSON](/es/reference/logger-reference/#loghandlersjson), lo cual es útil para una salida legible por máquina.

### `--ignore-lock`

<p><Since v="7.1.0" /></p>

Evita comprobar la existencia de un archivo de bloqueo y la necesidad de escribir uno. Esto permite que un nuevo servidor de desarrollo o, a partir de v7.3.0, un servidor de vista previa se inicie junto a un servidor que ya está en ejecución, en lugar de generar un error.

```shell
astro dev --ignore-lock --port 4322
```

El nuevo servidor no es rastreado por los [subcomandos comunes](#subcomandos-comunes).

Cuando se combina con [`--background`](#--background) o [`--force`](#--force), se produce un error, ya que ambos dependen del archivo de bloqueo.

## Banderas globales

Usa estas banderas para obtener información sobre la CLI de `astro`.

### `--version`

Muestra el número de versión de Astro y sale.

### `--help`

Muestra el mensaje de ayuda y sale.
