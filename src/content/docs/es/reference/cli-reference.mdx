Puedes utilizar la interfaz de línea de comandos (CLI) que ofrece Astro para desarrollar, construir y previsualizar tu proyecto desde el terminal.

### Comandos `astro`

Usa la CLI ejecutando uno de los **comandos** documentados en esta página con tu gestor de paquetes preferido, opcionalmente seguido de cualquier **opción**. Las opciones personalizan el comportamiento del comando.

Uno de los comandos que más vas a usar es `astro dev`. Este comando inicia el servidor de desarrollo y te da una vista previa en tiempo real, que se actualiza automáticamente en el navegador mientras trabajas:


### `package.json` scripts

También puedes usar scripts en el archivo `package.json` para crear abreviaciones de estos comandos. Utilizando un script puedes permitirte utilizar el mismo que utilizas en otros proyectos como por ejemplo `npm run build`.

Los comandos más comunes de `astro` (`astro dev`, `astro build`, and `astro preview`) son añadidos automáticamente cuando creas el proyecto usando [el asistente de instalación `create astro`](/es/install-and-setup/).

Cuando estés siguiendo las instrucciones para [instalar Astro manualmente](/es/install-and-setup/#manual-setup), se indica que añadas estos scripts por tu cuenta. También puedes añadir manualmente más scripts a la lista para cualquier comando que utilices con frecuencia.

```json title="package.json"
{
  "scripts": {
    "dev": "astro dev",
    "build": "astro build",
    "preview": "astro preview"
  }
}
```
Principalmente, usarás el comando `astro` o los scripts que los ejecutan sin opciones. Añade opciones a un comando cuando quieras modificar su comportamiento. Por ejemplo, es posible que quieras iniciar el servidor de desarrollo en un puerto diferente o compilar tú con registros para depuración.

  ```shell
  npm run build -- --verbose
  ```

## `astro dev`

Ejecuta el servidor de desarrollo de Astro. Es un servidor HTTP local que no incluye recursos. Utiliza el Reemplazo de Módulos en Caliente (HMR) para actualizar tu navegador mientras guardas tus cambios en tu editor.

Los siguientes atajos de teclado pueden usarse en el terminal donde se encuentra ejecutado el servidor de desarrollo de Astro:

- `s + enter` para sincronizar los datos de la capa de contenido (contenido y tipos).
- `o + enter` para abrir tu web Astro en el navegador.
- `q + enter` para detener el servidor de desarrollo.

El comando se puede combinar con [opciones comunes](#common-flags) y [subcomandos comunes](#common-subcommands) para controlar más la experiencia de desarrollo.

## `astro build`

Compila tu sitio para desplegar. Por defecto, esto va a generar archivos estáticos y colocarlos en la carpeta `dist/`. Si alguna ruta se [renderiza bajo demanda](/es/guides/on-demand-rendering/), esto va a generar los archivos necesarios de servidor para servir la página.

<h3>Opciones</h3>

Los comandos aceptan [opciones comunes](#common-flags) y las siguientes opciones adicionales:

#### `--devOutput`

<p><Since v="5.0.0" /></p>

Genera una compilación similar a `astro dev`. Esto puede ser útil para depurar errores durante la compilación, ya que muestra información adicional de depuración.

#### `--timings`

<p><Since v="7.4.0" /></p>

Muestra un resumen de cómo se distribuyó el tiempo durante el proceso de compilación, una vez finaliza. El informe cubre la fase de compilación, plug-ins Vite, el procesamiento de Markdown y el resaltado de sintaxis, renderizado de páginas, optimización de imágenes e integración de hooks.

## `astro preview`

Inicia un servidor local para mostrar el contenido de tu carpeta estática (`dist/` por defecto) creada al ejecutar `astro build`.

Este comando te permite previsualizar tu sitio localmente [después de compilar](#astro-build) para encontrar errores de compilación antes de ser desplegada. No está diseñada para ser ejecutada en producción. Para ayuda con el alojamiento en producción, echa un vistazo a nuestra guía en [Despliega tu sitio Astro](/es/guides/deploy/).

Los siguientes atajos de teclado pueden usarse en el terminal donde se encuentra ejecutado el servidor de previsualización de Astro:

- `o` + `enter` para abrir tu web Astro en el navegador.
- `q` + `enter` para detener el servidor de previsualización.

El comando se puede combinar con [opciones comunes](#common-flags) y [subcomandos comunes](#common-subcommands) para controlar más la experiencia de previsualización.

## `astro check`

Ejecuta un diagnóstico (como por ejemplo comprobación de tipos en los archivos `.astro`) en tu proyecto y muestra los errores en la consola. Si se encuentra algún error durante el proceso, se detendrá con el código **1**.

Este comando está pensado para utilizarse en flujos de trabajo CI.

<h3>Opciones</h3>

Utiliza estas opciones para modificar el comportamiento de los comandos.

#### `--watch`

El comando va a estar atento a cualquier cambio en tu proyecto e informará de cualquier error.

#### `--root <path-to-dir>`

Especifica un directorio raíz diferente para la revisión. Por defecto, utilizará el directorio actual.

#### `--tsconfig <path-to-file>`

Especifica manualmente un archivo `tsconfig.json` . Si no se proporciona ninguno, Astro intentará encontrar la configuración o deducirá automáticamente la configuración del proyecto.

#### `--minimumFailingSeverity <error|warning|hint>`

Especifica el nivel mínimo de gravedad necesario para detener el proceso. Por defecto es `error`.

Por ejemplo, ejecutando `astro check --minimumFailingSeverity warning` hará que el comando se detenga si hay algún error o advertencias detectadas.

#### `--minimumSeverity <error|warning|hint>`

Especifica la gravedad mínima para la compilación. Por defecto es `hint`.

Por ejemplo, ejecutando `astro check --minimumSeverity warning` muestra los errores y advertencias, pero no los consejos.

#### `--preserveWatchOutput`

Especifica no borrar las revisiones entre comprobaciones en el modo supervisión.

#### `--noSync`

Especifica no ejecutar `astro sync` al acabar de revisar el proyecto.

<ReadMore>Lee más acerca del [tipado en Astro](/es/guides/typescript/#type-checking).</ReadMore>

## `astro sync`

<p><Since v="2.0.0" /></p>

:::tip
Ejecutar `astro dev`, `astro build` o `astro check` va a ejecutar el comando `sync` también.
:::

Genera los tipos de TypeScript de todos los módulos Astro. Esto crea un [`.astro/types.d.ts` file](/es/guides/typescript/#setup) para la inferencia de tipos y define módulos para las funcionalidades que dependen de los tipos generados:

- El módulo `astro:content` para la [API de Colección de Contenidos](/es/guides/content-collections/).
- El módulo `astro:env` para las [Variables de Entorno](/es/guides/environment-variables/).
- El módulo `astro:actions` para [Acciones de Astro](/es/guides/actions/)

## `astro preferences`

Gestiona las preferencias de usuario mediante el comando `astro preferences`. Las preferencias de usuario son específicas para cada usuario de Astro; a diferencia del archivo `astro.config.mjs`, que modifica el comportamiento para todas las personas que trabajan en un proyecto.

Las preferencias de usuario están limitadas al proyecto actual por defecto, se guardan en un archivo local en `.astro/settings.json`.

Usando la opción `--global`, las preferencias de usuario pueden aplicarse a todos los proyectos de Astro en la máquina actual. Las preferencias globales se almacenan en una ubicación específica del sistema operativo.

<h3>Preferencias Disponibles</h3>

- `devToolbar` — Habilita o deshabilita la barra de herramientas de desarrollo en el navegador. (Por defecto: `true`)
- `checkUpdates` — Habilita o deshabilita la comprobación automática de actualizaciones para la CLI de Astro. (Por defecto: `true`)

El comando `list` muestra la configuración actual de todas las preferencias de usuario configurables. También admite una salida en formato `--json`.

```shell
astro preferences list
```

Ejemplo de salida en la terminal:

| Preference               | Value |
| ------------------------ | ----- |
| devToolbar.enabled       | true  <tr></tr>|
| checkUpdates.enabled     | true  |

Puedes `enable`, `disable`, o `reset` las preferencias a su valor por defecto.

Por ejemplo, para deshabilitar la barra de herramientas en un proyecto de Astro específico:

```shell
astro preferences disable devToolbar
```
Para deshabilitar la barra de herramientas en todos los proyectos de Astro en tu máquina actual:

```shell
astro preferences disable --global devToolbar
```

Se puede volver habilitar la barra de herramientas con:

```shell
astro preferences enable devToolbar
```

El comando `reset` resetea la preferencia a su valor por defecto:

```shell
astro preferences reset devToolbar
```

## `astro telemetry`

Establece la configuración de telemetría para el usuario actual de la CLI. La telemetría consiste en datos anónimos que proporcionan al equipo de Astro qué funcionalidades son las más utilizadas. Para más información revisa [telemetría de Astro](https://astro.build/telemetry/).

La telemetría se puede deshabilitar con el comando de CLI:

```shell
astro telemetry disable
```

La telemetría se puede  volver a habilitar con:

```shell
astro telemetry enable
```

El comando `reset` resetea los datos de telemetría:

```shell
astro telemetry reset
```

:::tip[Quieres deshabilitar la telemetría en entornos CI?]
Añade el comando `astro telemetry disable` a tus scripts de CI o establece la variable de entorno `ASTRO_TELEMETRY_DISABLED`.
:::

## `astro create-key`

Genera una clave para cifrar parámetros que se pasan a las islas de servidor.

```shell
astro create-key
```
Configura esta clave `ASTRO_KEY` como variable de entorno (por ejemplo en el archivo `.env`) y la incluyen la configuración de compilación del CI/CD o de tu plataforma de alojamiento cuando necesites [una clave consistente para tus islas de servidor](/es/guides/server-islands/#reusing-the-encryption-key). Esto es útil en situaciones como despliegues graduales, alojamiento en múltiples regiones o el uso de una red de distribución de contenidos (CDN) que almacene en caché páginas que contengan islas de servidor.

## Subcomandos comunes

<p><Since v="7.0.0" /></p>

El comando [`astro dev`](#astro-dev) y, desde la versión v7.2.0, [`astro preview`](#astro-preview) admiten los siguientes subcomandos para gestionar el [servidor en segundo plano](#--background).

### `stop`

Detiene el servidor en segundo plano. Envía `SIGTERM` y espera hasta 5 segundos para que el servidor se detenga sin problemas. Si el proceso sigue ejecutándose después de estos segundos, se escala a `SIGKILL`.

### `status`

Comprueba si hay un servidor en ejecución y muestra su URL, PID, y tiempo de actividad.

### `logs`

Muestra los registros del servidor. Solo funciona cuando el servidor ha sido iniciado con la opción [`--background` flag](#--background), ya que los servidores lanzados en primer plano escriben los registros directamente en el terminal.

#### Flags

##### `--follow` (`-f`)

Transmite el nuevo contenido del registro a medida que se escribe, de forma similar a `tail -f`. Sin esta opción, se muestra el contenido actual del archivo de registro y el comando finaliza.

## Common flags

### `--root <path>`

Especifica la ruta al proyecto raíz. Si no se especifica, el directorio actual es establecido como raíz.

El directorio raíz se utiliza para encontrar los archivos de configuración de Astro.

```shell
astro --root myRootFolder/myProjectFolder dev
```
### `--config <path>`

Especifica la ruta al archivo de configuración del proyecto raíz. El valor predeterminado es `astro.config.mjs`. Utiliza esta opción si empleas un nombre distinto para tu archivo de configuración o si este se encuentra en otra carpeta.

```shell
astro --config config/astro.config.mjs dev
```

### `--force`

<p><Since v="5.0.0" /></p>

Limpia la caché de la capa de contenido, forzando una compilación completa.

### `--mode <string>`

<p><Since v="5.0.0" /></p>

Configura el [`modo`](/es/reference/programmatic-reference/#astroinlineconfigmode) de configuración en línea para tu proyecto.

### `--outDir <path>`

<p><Since v="3.3.0" /></p>

Configura el [`outDir`](/es/reference/configuration-reference/#outdir) para el proyecto. Pasar esta opción va a sobreescribir el valor de `outDir` en tu archivo `astro.config.mjs`, si existe.

### `--site <url>`

Configura la [`página`](/es/reference/configuration-reference/#site) para tu proyecto. Pasar esta opción va a sobreescribir el valor de `site` en tu archivo `astro.config.mjs`, si existe.

### `--base <pathname>`

<p><Since v="1.4.1" /></p>

Configura la [`base`](/es/reference/configuration-reference/#base) para tu proyecto. Pasar esta opción va a sobreescribir el valor de `base` en tu archivo `astro.config.mjs`, si existe.

### `--port <number>`

Especifica el puerto en el que se ejecutará el servidor de desarrollo y previsualización. Por defecto `4321`.

### `--host [dirección host opcional]`

Configura qué dirección IP el servidor de desarrollo y previsualización deben escuchar (direcciones IP distintas de localhost). Esto puede ser útil para probar el proyecto en dispositivos locales como el teléfono durante el desarrollo.

- `--host` — escucha en todas las direcciones, incluyendo LAN y direcciones públicas.
- `--host <dirección personalizada>` — exponer en una dirección IP en `<dirección personalizada>`.

:::caution
No se debe utilizar la opción `--host` para exponer el servidor de desarrollo y previsualización en un entorno de producción. Estos servidores están diseñados para el uso local durante el desarrollo de tu web.
:::

### `--allowed-hosts`

<p><Since v="5.4.0" /></p>

Especifica los nombres de host a los que Astro tiene permitido responder en los modos `dev` o `preview`. Se puede proporcionar una lista de nombres de host separados por comas, o bien el valor `true` para permitir cualquier nombre de host.

Consulta la funcionalidad de [`allowedHosts` de Vite](https://vite.dev/config/server-options.html#server-allowedhosts) para más información, incluidas las implicaciones de seguridad de permitir nombres de host.

### `--verbose`

Habilita los registros detallados, lo que es útil para depuración de errores.

### `--silent`

Habilita los registros silenciosos, lo que va a ejecutar el servidor sin salida por el terminal.

### `--open`

Abre automáticamente la aplicación en el navegador al iniciar el servidor. Se puede proporcionar una URL completa (por ejemplo, `--open http://example.com`) o una ruta (por ejemplo, `--open /about`) para especificar la URL que se debe abrir.

### `--background`

<p><Since v="7.0.0" /></p>

Inicia el servidor de desarrollo o el de previsualización desde la v7.2.0, como un proceso en segundo plano independiente y habilita los [registros en formato JSON](#--json).

Al iniciar el servidor, Astro crea un archivo de bloqueo (`.astro/dev.json` o `.astro/preview.json`) para registrar la URL, el puerto y el PID del servidor. Esto evita que se inicien múltiples instancias del servidor para un mismo proyecto.

Esta opción se aplica automáticamente cuando se detecta un agente de IA en macOS y Linux. En Windows, no se produce la ejecución automática en segundo plano: si se detecta un agente de IA, el servidor permanece en primer plano para que dicho agente pueda gestionar el proceso directamente. En todas las plataformas, también es posible utilizar esta opción de forma manual:

```shell
astro dev --background
```

Si ya hay un servidor en ejecución del proyecto, el comando muestra la información de dicho servidor y finaliza sin iniciar uno nuevo. Utiliza la opción --force para detener el servidor existente e iniciar uno nuevo.

```shell
astro dev --background --force
```

<ReadMore>Lee acerca del [Modo en segundo plano para agentes con IA](/es/guides/build-with-ai/#background-mode) para más información sobre la detección automática de agentes y los endpoints de estado.</ReadMore>

### `--json`

<p><Since v="7.0.0" /></p>

Habilita el [registro en formato JSON](/es/reference/logger-reference/#loghandlersjson), lo cual resulta útil para obtener una salida legible por máquinas.

### `--ignore-lock`

<p><Since v="7.1.0" /></p>

Evita que se compruebe la existencia de un archivo de bloqueo y que sea necesario crear uno. Esto permite que un nuevo servidor de desarrollo o desde la versión 7.3.0 uno de previsualización pueda iniciarse junto a otro servidor que ya esté en ejecución, en lugar de provocar un error.

```shell
astro dev --ignore-lock --port 4322
```

The new server is not tracked by the [common subcommands](#common-subcommands).

When combined with [`--background`](#--background) or [`--force`](#--force), an error is thrown, as both rely on the lock file.
