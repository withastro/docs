<p><Since v="7.0.0" /></p>

El módulo `astro/fetch` ofrece controladores de [enrutamiento avanzado](/es/guides/routing/#enrutamiento-avanzado) basados en la API estándar de búsqueda.

## Importaciones desde `astro/fetch`

```ts
import {
  FetchState,
  astro,
  cache,
  i18n,
  middleware,
  notFound,
  pages,
  redirects,
  sessions,
  trailingSlash,
} from 'astro/fetch';
```

### `FetchState`

El objeto de estado por solicitud. Crea uno al inicio de tu método `fetch`:

```ts {5} title="src/fetch.ts"
import { FetchState } from 'astro/fetch';

export default {
  async fetch(request: Request): Promise<Response> {
    const state = new FetchState(request);
    // Tu lógica de enrutamiento avanzado...
  },
};
```

`FetchState` registra la ruta coincidente, las cookies, los proveedores de sesión y otros datos específicos de cada solicitud. Todas las funciones de control lo requieren como primer argumento.

<ReadMore>Aprende a [componer controladores](/es/guides/routing/#composición-de-controladores-individuales) con `FetchState` en la guía de enrutamiento avanzado.</ReadMore>

#### Propiedades

##### `state.request`

<p>

**Tipo:** `Request`
</p>

El objeto [Request](https://developer.mozilla.org/es/docs/Web/API/Request) entrante.

##### `state.url`

<p>

**Tipo:** `URL`
</p>

Una [URL](https://developer.mozilla.org/es/docs/Web/API/URL) normalizada derivada de la solicitud.

##### `state.pathname`

<p>

**Tipo:** `string`
</p>

La ruta de la solicitud sin la base y descodificada (p. ej., `/sobre-mí` o `/blog/mi-artículo`).

##### `state.routeData`

<p>

**Tipo:** <code><a href="/es/reference/integrations-reference/#routedata">RouteData</a> | undefined</code>
</p>

La ruta coincidente para esta solicitud, si la hay. Esto se resuelve automáticamente al crear el `FetchState`.

##### `state.cookies`

<p>

**Tipo:** `AstroCookies`
</p>

Una instancia de [`AstroCookies`](/es/reference/api-reference/#cookies) para leer y configurar cookies en esta solicitud.

##### `state.locals`

<p>

**Tipo:** `App.Locals`
</p>

Un objeto con ámbito de solicitud para almacenar datos personalizados. Se trata del mismo objeto [`locals`](/es/reference/api-reference/#locals) disponible en [middleware](/es/guides/middleware/) y en [rutas de la API](/es/guides/endpoints/#server-endpoints-api-routes).

##### `state.params`

<p>

**Tipo:** `Params | undefined`
</p>

Parámetros de ruta derivados de la ruta y el nombre de ruta coincidentes (p. ej., `{ slug: 'mi-artículo' }`). `undefined` cuando la ruta no coincide o no tiene parámetros.

##### `state.session`

<p>

**Tipo:** <code><a href="/es/reference/api-reference/#session">AstroSession</a> | undefined</code>
</p>

El objeto de sesión para esta solicitud. Solo está disponible después de llamar al controlador [`sessions()`](#sessions).

### `astro()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>) => Promise\<Response\></code>
</p>

El controlador de enrutamiento predeterminado. Gestiona la caché, las redirecciones, las barras diagonales finales, la internacionalización, las sesiones y el renderizado en el orden estándar de Astro:

```ts {6} title="src/fetch.ts"
import { FetchState, astro } from 'astro/fetch';

export default {
  async fetch(request: Request): Promise<Response> {
    const state = new FetchState(request);
    return astro(state);
  },
};
```

`astro()` equivale a encadenar manualmente todos los controladores individuales en el orden recomendado. Usa controladores individuales cuando necesites insertar lógica personalizada entre los pasos de enrutamiento.

### `cache()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>) => Promise\<Response\> | undefined</code>
</p>

Comprueba si la solicitud entrante puede ser atendida por la caché. Si es así, devuelve una `Response` en caché. Si la ruta es dinámica o la página no está en caché, devuelve `undefined`.

### `i18n()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>) => Promise\<Response\> | undefined</code>
</p>

Gestiona la redirección y el enrutamiento [i18n](/es/guides/internationalization/). Devuelve una respuesta de redirección si la solicitud coincide con una regla de redirección de idioma (p. ej., redirigir a un prefijo de idioma predeterminado), o `undefined` si el procesamiento de la solicitud debe continuar. Llama a esta función al principio de tu pipeline (después de `cache()`):

```ts {6} title="src/fetch.ts"
import { FetchState, i18n } from 'astro/fetch';

export default {
  async fetch(request: Request): Promise<Response> {
    const state = new FetchState(request);
    const redirect = await i18n(state);
    if (redirect) return redirect;
    // ...resto del pipeline...
  },
};
```

### `middleware()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>, next: (state: FetchState) => Promise\<Response\>) => Promise\<Response\></code>
</p>

Ejecuta el [middleware](/es/guides/middleware/) del proyecto. Acepta la función `FetchState` y una función `next` que se llama con el estado (potencialmente modificado) para continuar con el pipeline. Normalmente, envolverías `pages(state)`:

```ts {7} title="src/fetch.ts"
import { FetchState, middleware, pages } from 'astro/fetch';

export default {
  async fetch(request: Request): Promise<Response> {
    const state = new FetchState(request);
    const response = await middleware(state, (s) => pages(s));
    return response;
  },
};
```

### `notFound()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>) => Promise\<Response\> | undefined</code><br />
<Since v="7.4.0" />
</p>

Renderiza tu [página 404 personalizada](/es/basics/astro-pages/#página-de-error-404-personalizada), incluyendo un `404.astro` prerenderizado, cuando ninguna ruta coincide. Esto devuelve `undefined` para una ruta coincidente o una respuesta `400` vacía para una ruta de solicitud con codificación excesiva. La función que la invoca puede decidir entonces si continuar con el procesamiento.

[`astro()`](#astro) ya incluye este manejo. Cuando compongas controladores individuales en su lugar, añade `notFound()` antes de [`middleware()`](#middleware) y [`pages()`](#pages) para renderizar la página 404 para rutas no coincidentes:

```ts {6,7} title="src/fetch.ts"
import { FetchState, middleware, notFound, pages } from 'astro/fetch';

export default {
  async fetch(request: Request): Promise<Response> {
    const state = new FetchState(request);
    const notFoundResponse = await notFound(state);
    if (notFoundResponse) return notFoundResponse;
    return middleware(state, (s) => pages(s));
  },
};
```

### `pages()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>) => Promise\<Response\></code>
</p>

Envía la solicitud a la ruta de Astro correspondiente (página, endpoint o fallback). Este es el controlador de renderizado principal, y la mayoría de los pipelines personalizados lo incluirán.

Añade [`notFound()`](#notfound) antes de `pages()` para renderizar tu página 404 personalizada para rutas no coincidentes.

### `redirects()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>) => Promise\<Response\> | undefined</code>
</p>

Gestiona las rutas de redirección definidas en tu [configuración de Astro](/es/reference/configuration-reference/#redirects). Devuelve una `Response` de redirección si la ruta coincidente es una redirección, o `undefined` si la función que la invoca debe continuar con el procesamiento.

### `sessions()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>) => Promise\<void\> | void</code>
</p>

Registra el proveedor de una [sesión](/es/guides/sessions/). Las sesiones se crean de forma diferida cuando tu código accede a `ctx.session` y se guardan automáticamente al final de la solicitud. Llama a esta función al principio del pipeline (antes de que se ejecute el middleware):

```ts {6} title="src/fetch.ts"
import { FetchState, sessions } from 'astro/fetch';

export default {
  async fetch(request: Request): Promise<Response> {
    const state = new FetchState(request);
    await sessions(state);
    // ...pipeline de renderizado...
  },
};
```

Este controlador no registra ningún proveedor cuando no hay ningún controlador de sesión configurado, o cuando [las sesiones están deshabilitadas](/es/guides/sessions/#disabling-sessions). En ambos casos, `ctx.session` será `undefined`.

### `trailingSlash()`

<p>

**Tipo:** <code>(state: <a href="#fetchstate">FetchState</a>) => Response | undefined</code>
</p>

Comprueba si la ruta de la solicitud necesita normalización con [barra final](/es/reference/configuration-reference/#trailingslash) y, en caso afirmativo, devuelve una `Response` de redireccionamiento. Devuelve `undefined` cuando no es necesario ningún redireccionamiento.
