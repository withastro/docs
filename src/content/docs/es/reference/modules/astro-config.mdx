Este módulo virtual `astro:config` expone una versión no exhaustiva, serializable y con seguridad de tipos de la configuración de Astro. Hay dos submódulos para acceder a diferentes subconjuntos de tus valores de configuración: [`/client`](#importaciones-desde-astroconfigclient) y [`/server`](#importaciones-desde-astroconfigserver).

Todos los valores de configuración disponibles pueden accederse desde `astro:config/server`. Sin embargo, para el código ejecutado en el cliente, solo estarán disponibles aquellos valores expuestos por `astro:config/client`. Esto protege tu información haciendo que solo algunos datos estén disponibles para el cliente.

## Importaciones desde `astro:config/client`

Las siguientes funciones auxiliares se importan desde el directorio `client` del módulo de configuración virtual.

```js
import {
  i18n, 
  trailingSlash,
  base,
  build,
  site,
  compressHTML,
} from "astro:config/client";
```

Usa este submódulo para código del lado del cliente:

```js title="src/utils.js" ins={1} ins="trailingSlash"
import { trailingSlash } from "astro:config/client";

function addForwardSlash(path) {
  if (trailingSlash === "always") {
    return path.endsWith("/") ? path : path + "/"
  } else {
    return path
  }
}
```

## Importaciones desde `astro:config/server`

Las siguientes funciones auxiliares se importan desde el directorio `server` del módulo de configuración virtual.

```js
import {
  i18n, 
  trailingSlash,
  base,
  build,
  site,
  srcDir,
  cacheDir,
  outDir,
  publicDir,
  root,
  compressHTML,
} from "astro:config/server";
```

Estas importaciones incluyen todo lo disponible desde `astro:config/client`, así como información confidencial adicional sobre la configuración de tu sistema de archivos que no es seguro exponer al cliente.

Usa este submódulo para código del lado del servidor:

```js title="astro.config.mjs"
import { integration } from "./integration.mjs";

export default defineConfig({
    integrations: [
      integration(),
    ]
});
```

```js title="integration.mjs" ins={1} ins="outDir"
import { outDir } from "astro:config/server";
import { writeFileSync } from "node:fs";
import { fileURLToPath } from "node:url";

export default function() {
  return {
    name: "internal-integration",
    hooks: {
      "astro:build:done": () => {
        let file = new URL("result.json", outDir);
        // genera datos a partir de alguna operación
        let data = JSON.stringify([]);
        writeFileSync(fileURLToPath(file), data, "utf-8");
      }
    }
  }
}
```

## Importaciones desde `astro/config`

Las siguientes funciones auxiliares se importan desde el módulo de configuración regular:

```js
import {
  defineConfig,
  envField,
  fontProviders,
  getViteConfig,
  memoryCache,
  logHandlers,
  mergeConfig,
  passthroughImageService,
  sessionDrivers,
  sharpImageService,
  validateConfig,
} from "astro/config";
```

### `defineConfig()`

<p>

**Tipo:** <code>(config: <a href="/es/reference/configuration-reference/">AstroUserConfig</a>) => AstroUserConfig</code>
</p>

Configura tu proyecto con seguridad de tipos [en un archivo de configuración de Astro compatible](/es/guides/configuring-astro/#el-archivo-de-configuración-de-astro).

### `envField`

<p>

**Tipo:** `object`<br />
<Since v="5.0.0" />
</p>

Describe los tipos de datos admitidos al [definir variables de entorno](/es/reference/configuration-reference/#envschema).

Cada tipo de datos debe definir el [tipo de variable](/es/guides/environment-variables/#tipos-de-variables) con `context` (`"client"` o `"server"`) y `access` (`"secret"` o `"public"`). Además, puedes definir un valor `default`, especificar si la variable es `optional` (por defecto `false`), y algunos tipos de datos proporcionan métodos de validación opcionales.

<ReadMore>Aprende más sobre el [uso de variables de entorno con seguridad de tipos](/es/guides/environment-variables/#variables-de-entorno-con-seguridad-de-tipos) en tu proyecto de Astro.</ReadMore>

#### `envField.string()`

<p>

**Tipo:** `(options: StringFieldInput) => StringField`
</p>

Define una variable de entorno de tipo string. Puedes realizar [validación de strings con Zod](https://zod.dev/api#strings) usando las siguientes propiedades: `max`, `min`, `length`, `url`, `includes`, `startsWith` y `endsWith`.

El siguiente ejemplo define la estructura esperada para una variable de entorno que almacena una URL de API:

```js title="astro.config.mjs" "envField"
import { defineConfig, envField } from "astro/config";

export default defineConfig({
  env: {
    schema: {
      API_URL: envField.string({
        context: "client",
        access: "public",
        optional: false,
        default: "",
        min: 12,
        url: true,
        includes: "astro",
        startsWith: "https",
      }),
    }
  }
})
```

#### `envField.number()`

<p>

**Tipo:** `(options: NumberFieldInput) => NumberField`
</p>

Define una variable de entorno de tipo numérico. Puedes realizar [validación de números con Zod](https://zod.dev/api#numbers) usando las siguientes propiedades: `gt`, `lt`, `min`, `max` e `int`.

El siguiente ejemplo define la estructura esperada para una variable de entorno que almacena un puerto de API:

```js title="astro.config.mjs" "envField"
import { defineConfig, envField } from "astro/config";

export default defineConfig({
  env: {
    schema: {
      API_PORT: envField.number({
        context: "server",
        access: "public",
        optional: true,
        default: 4321,
        min: 2,
        int: true,
      }),
    }
  }
})
```

#### `envField.boolean()`

<p>

**Tipo:** `(options: BooleanFieldInput) => BooleanField`
</p>

Define una variable de entorno de tipo booleano.

El siguiente ejemplo define la estructura esperada para una variable de entorno que almacena si las analíticas están habilitadas:

```js title="astro.config.mjs" "envField"
import { defineConfig, envField } from "astro/config";

export default defineConfig({
  env: {
    schema: {
      ANALYTICS_ENABLED: envField.boolean({
        context: "client",
        access: "public",
        optional: true,
        default: true,
      }),
    }
  }
})
```

#### `envField.enum()`

<p>

**Tipo:** `(options: EnumFieldInput<T>) => EnumField`
</p>

Define una variable de entorno de tipo enum proporcionando los `values` permitidos como un array.

El siguiente ejemplo define la estructura esperada para una variable de entorno que almacena el modo de depuración configurado:

```js title="astro.config.mjs" "envField" {9}
import { defineConfig, envField } from "astro/config";

export default defineConfig({
  env: {
    schema: {
      DEBUG_MODE: envField.enum({
        context: "server",
        access: "public",
        values: ['info', 'warnings', 'errors'], // requerido
        optional: true,
        default: 'errors',
      }),
    }
  }
})
```

### `passthroughImageService()`

<p>

**Tipo:** <code>() => <a href="/es/reference/modules/astro-assets/#imageserviceconfig">ImageServiceConfig</a></code>
</p>

Recupera un servicio de imágenes no-op. Esto es útil cuando tu adaptador no es compatible con la optimización de imágenes Sharp integrada de Astro y deseas [usar los componentes `<Image />` y `<Picture />`](/es/guides/images/#componentes-astro-para-imágenes).

El siguiente ejemplo define `passthroughImageService()` como servicio de imágenes en el archivo de configuración de Astro para evitar el procesamiento de imágenes de Sharp:

```js title="astro.config.mjs" "passthroughImageService"
import { defineConfig, passthroughImageService } from "astro/config";

export default defineConfig({
  image: {
    service: passthroughImageService()
  }
});
```

<ReadMore>Aprende más sobre cómo [configurar un servicio de paso a través no-op](/es/guides/images/#configurar-un-servicio-de-paso-a-través-no-op).</ReadMore>

### `sessionDrivers`

<p>

**Tipo:** `object`<br />
<Since v="5.7.0" />
</p>

Describe el [controlador integrado](/es/reference/session-driver-reference/#built-in-drivers) utilizado [para el almacenamiento de sesiones](/es/reference/configuration-reference/#session-options).

El siguiente ejemplo configura el controlador de Redis para habilitar las sesiones:

```js title="astro.config.mjs" "sessionDrivers"
import { defineConfig, sessionDrivers } from "astro/config";

export default defineConfig({
  session: {
    driver: sessionDrivers.redis({
      url: process.env.REDIS_URL
    }),
  }
})
```

<ReadMore>Aprende más sobre [el uso de sesiones](/es/guides/sessions/) en tu proyecto de Astro.</ReadMore>
